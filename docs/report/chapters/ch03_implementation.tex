\subsection{Partitioning and Fault Injection}
\label{sec:impl-partitioning}
\label{sec:impl-faults}

\code{fleet.telemetry} has 6 partitions \textbf{keyed by
\code{vehicle\_id}}. Kafka orders events only within a partition, and
the per-vehicle idle state machine assumes it sees each vehicle's events
in order, so keying is a correctness decision, not a throughput one.
Rejected events go to \code{fleet.telemetry.dlq} with a reason code and
the original payload, so they can be replayed.

The simulator corrupts its own output (Table~\ref{tab:faults}).
Validation \emph{rejects rather than repairs}: a coerced field would
produce a confidently wrong money figure. A second simulator drops one
versioned expense CSV per simulated day; a corrected \code{v2} for a
reconciled day triggers recomputation (Section~\ref{sec:recompute}).

\section{The Speed Layer}
\label{sec:impl-speed}

\textbf{Archiver.} \label{sec:impl-archiver} A separate Spark application
with its own checkpoint and \emph{no business logic}, so a bug in the
speed layer cannot corrupt the master dataset. Unparseable records are
kept under \code{sim\_date=unknown}.

\textbf{Stateful idle alerts.} \label{sec:impl-idle} ``Idle for 45
simulated minutes?'' needs per-vehicle memory across micro-batches and
must fire even when no event arrives, so it uses
\code{applyInPandasWithState}. The timer starts on the
\emph{transition} into idle; events are sorted by event time before
folding; a stale out-of-order event does not rewind state; and an
\code{EventTimeTimeout} is used so the rule does not depend on clock
compression. Because event-time timeouts need the watermark to advance, a
fleet-wide silence is covered separately by the
\code{TelemetryNotProduced} alert.

\textbf{Idempotent sinks.} \label{sec:impl-sinks} \code{foreachBatch} is
at-least-once, so every sink upserts on a natural key
(\code{rt\_vehicle\_state} on \code{vehicle\_id}, \code{rt\_zone\_hourly}
on \code{(zone\_id, window\_start)}, \code{rt\_vehicle\_daily} on
\code{(vehicle\_id, sim\_date)}, \code{idle\_alerts} on
\code{(vehicle\_id, opened\_at)}). A replayed batch rewrites the same
values, and \code{update} output mode shows the current hour live.

\section{The Batch Layer and Orchestration}
\label{sec:impl-batch}
\label{sec:impl-trust}

\code{compute\_vehicle\_day} re-reads the raw archive and re-applies
validation and deduplication itself, with \textbf{no watermark}; it never
reads speed-layer output, so the drift measurement compares two
independent computations. It produces per vehicle-day trips, revenue,
GPS distance, online/on-trip/idle minutes and utilisation. Telemetry and
expenses are joined with a \textbf{full outer join} so that vehicles with
no cost record (\code{missing\_costs}) and cost records with no telemetry
(\code{missing\_telemetry}) are flagged rather than silently dropped.

Airflow runs in real time, so the nine-task DAG polls every 2 real
minutes and its first task picks the pending simulated day.
\code{load\_batch\_views} deletes and re-inserts a date's rows in one
transaction, making recomputation idempotent and atomic.

\section{Serving}
\label{sec:impl-serving}
\label{sec:impl-merge}

Both layers write to one PostgreSQL instance. FastAPI exposes eleven
endpoints (Appendix~\ref{app:api}), including the daily report at
\code{GET /reports/\{sim\_date\}}, and two Grafana dashboards read the
same tables. \code{GET /vehicles/\{id\}} returns \code{live} and
\code{today} blocks labelled \code{"source": "speed"} and a
\code{history} block labelled \code{"source": "batch"} --- never blended,
so a dashboard estimate cannot end up in a financial statement.

\section{Observability}
\label{sec:impl-observability}
\label{sec:impl-alerting}

Metrics answer four questions: \emph{is data arriving}
(\code{fleet\_events\_produced\_total}), \emph{is it processed}
(per-query \code{fleet\_stream\_last\_progress\_timestamp}), \emph{is it
correct} (\code{fleet\_dlq\_events\_total},
\code{fleet\_late\_rows\_dropped\_total},
\code{fleet\_speed\_batch\_drift\_ratio}), and \emph{is the business
healthy} (\code{fleet\_open\_idle\_alerts}). Kafka lag is read from
Spark's query progress, because Structured Streaming does not commit
consumer-group offsets. Batch outcomes are exported by the API from
PostgreSQL instead of a Pushgateway, since Airflow tasks exit before
Prometheus scrapes.

Every log line is a JSON object with \code{service}, \code{stage},
\code{event} and \code{sim\_time}. Instead of distributed tracing we
propagate correlation IDs: \code{event\_id}, \code{vehicle\_id},
\code{run\_id} and \code{sim\_date} link a DLQ entry or a reconciled
figure back to its source. Ten alert rules are defined
(Appendix~\ref{app:alerts}).
