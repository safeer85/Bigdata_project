\chapter{Conclusions and Recommendations}
\label{ch:conclusion}

The brief's question is two questions with incompatible latency, accuracy
and recomputability requirements. Lambda is justified here by one
property Kappa cannot supply cheaply: \textbf{restating a past day's
figures when a correction arrives on a different channel, days later.}
A corrected file produced the same 50 rows with updated values, and a
forced replay was bit-identical. We measured the
speed layer's approximation rather than asserting it, explained why it
is usually zero, and contained Lambda's two-codebase weakness with the
shared \code{common/} package and parity tests.

\section*{Recommendations}

\begin{enumerate}
  \item Run the archiver and speed layer on separate workers.
  \item Add a schema registry and an automated DLQ replay path.
  \item Adopt a lake table format (Iceberg or Delta Lake) for atomic
        partition writes.
  \item Annotate outage windows and use ratio-based alert thresholds.
\end{enumerate}
